RUNBOOKLegacy PayPal to modern PayPal

Cutover day is the scariest day.

A migration agent for developers. Cutover rewrites an old PayPal integration to PayPal's modern stack, then proves in the sandbox that checkout still pays. Go or no-go, with evidence.

HOW IT WORKSFor the developer doing the migration

Run it, review it, trust the proof

The shop owner should notice nothing: customers pay the same way. The work is underneath, where old PayPal code (classic NVP API, checkout.js v4, IPN) has to move to the modern stack. Cutover is the developer's assistant for that job. Nothing is applied automatically; a person reviews and merges.

STEP 01Discover

What is really in there

A deterministic scan of the legacy shop. Each touchpoint shows what it is today, what it becomes, and how sure the mapping is. Anything it cannot map goes to a human, never guessed.

DOCUMENTED it is in PayPal's official upgrade guide. INFERRED standard behaviour, confirmed by the sandbox run rather than by the guide. UNMAPPED no safe equivalent, left for a human.

STEP 02Rewrite

A diff a person can approve

Nothing is applied automatically. The migrated shop goes to a separate folder and every change is listed here for review.

STEP 03Check and repair

The AI got it wrong. Cutover caught it.

Real mistakes from real runs. Automatic checks found each one and sent the failure back to the model. The shop only moved on once every check was green.

STEP 04Prove

Proof, not trust

The same seven scenarios ran against the old and migrated shops in a real browser, as a sandbox buyer. After every payment, PayPal itself was asked what happened.

HONEST LIMITSWhat this does not do yet

Where the evidence stops

  • One stack. The recorded run covers PHP shops on the classic NVP API, checkout.js v4 and IPN. Other languages and setups need new mapping rules.
  • One recorded run. AI output varies between runs. The checks and the 7 scenarios are what make a result trustworthy, not the model. A re-run can take a different number of repair rounds.
  • Seven scenarios, not every path. Single and multi-item payment, cancel, refund, refund twice, replayed confirmation and empty cart. Subscriptions, card-only checkout and billing agreements are flagged for a human, not migrated.
  • The demo shops are sandbox only. The old shop is deliberately weak (open refund endpoint, weak IPN check) because that is what real legacy code looks like. Never reuse it with real money.
